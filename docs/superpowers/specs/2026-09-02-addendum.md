# compositionfactory — Shipped Capabilities Addendum

**Status:** Shipped · **Date:** 2026-09-02 · **Repo:** `koorikla/compositionfactory`

This addendum documents the capabilities, architecture extensions, and systems shipped since the original [2026-08-27 Design Specification](2026-08-27-compositionfactory-design.md).

---

## 1. Multi-Emitter Engine & Schema Validation

The core engine (`internal/emit`) was expanded to support multiple generation targets while keeping `internal/emit` as the single authoritative source of truth for both CLI and API:

- **Emitters**:
  - **Go-Templating**: Generates Crossplane v2 Compositions powered by `function-go-templating` with deterministic whitespace formatting and automated template defaulting.
  - **KCL**: Generates Crossplane v2 Compositions using `function-kcl` emitting typed `KCLInput` models targeting `oxr` (observed composite resource) and `ocds` (observed composed desidered state).
- **OpenAPI v3 Schema Validation**:
  - Validates all resource `fields` against real `spec.forProvider` CRD OpenAPI schemas.
  - Identifies invalid field paths at blueprint load/edit/generate time, providing nearest-match suggestions (e.g. `spec.forProvider.tag` -> did you mean `tags`?).
- **Wiring & Guard Architecture**:
  - Deep nested parameter references (`params.<object>.<member>...`) with multi-level `chainGuard` emission under `options: ["missingkey=error"]`.
  - Cross-resource status references (`status.atProvider.*`) with automatic left-to-right visual DAG placement and ready-state dependency coordination.
  - Envelope and annotation field bindings (`metadata.annotations`, `metadata.labels`).
- **Automated RBAC Derivation**:
  - Scans composed CRD kinds and produces Kubernetes `ClusterRole` manifests declaring exact RBAC permissions required for Crossplane composite controllers.

## 2. Provider Management, Catalogue & Live Cluster Discovery

- **Zero-Docker OCI Layer Extraction (`internal/xpkg`)**:
  - Direct OCI layer extraction (`io.crossplane.xpkg:<digest>=base`), downloading only CRD metadata layers without pulling entire runtime images (~13,500:1 size reduction).
  - Dependency crawling (`spec.dependsOn`) and Upjet family resolution, caching full provider families (AWS, GCP, Azure) to support cross-group references.
- **Built-in Provider Catalogue (`catalogue/`, `scripts/build-catalogue`)**:
  - Offline-accessible embedded catalogue containing 476+ open-source Crossplane provider packages.
  - Fast search, version filtering, and single-click schema pulling.
- **Live Kubernetes Cluster Discovery (`internal/cluster`, `internal/api/cluster.go`)**:
  - Connects to active Kubernetes clusters via kubeconfig contexts.
  - Dynamically queries and caches all cluster-installed CustomResourceDefinitions (`apiextensions.k8s.io/v1`), allowing authoring against in-cluster custom resources alongside OCI providers.

## 3. Composition Adoption Engine (`internal/adopt`)

- Reverse-engineers existing Crossplane Composition and XRD YAML manifests.
- Converts opaque pipelines into structured `Blueprint` IR (`factory.crossplane.io/v1alpha1`), automatically inferring:
  - Declared parameters and types.
  - Composed resources and provider package mapping.
  - Static field values, template patches, and dynamic wire bindings.
- Accessible via CLI (`cf adopt`), HTTP API (`POST /api/blueprint/adopt`), and MCP tool (`adopt_composition`).

---

## 4. Visual Canvas Frontend (`web-proto`)

Embedded zero-dependency, ultra-lightweight visual workspace served directly from the Go binary via `embed.FS`:

- **Interactive Topology**:
  - Drag-and-drop kind placement from the schema palette.
  - Dot-to-card and port-to-port wire drawing for parameters and status fields.
  - Selection synchronization between canvas nodes, inspector forms, and generated YAML lines.
- **Inspector Panel**:
  - Required / Set / All field filtering.
  - Tri-mode field inputs: **V** (Literal Value), **W** (Wire to parameter), and **R** (Raw template).
- **Artifact & File Tree Explorer**:
  - Hierarchical drawer displaying generated XRDs, Compositions, Functions, Blueprints, and RBAC rules.
  - Live CodeMirror syntax highlighting with one-click copy and export.
- **Window Management & Ergonomics**:
  - Free-floating, draggable, and collapsible window panels.
  - Keyboard shortcuts (`Ctrl+B` toggle drawer) and Dark / Light / System theme switching.
- **Live Render Verification**:
  - Background `crossplane composition render` execution against synthesized test XRs with real-time status chips and error feedback.
- **Curated Starter Blueprints**:
  - Built-in instant templates (IRSA on AWS, RDS PostgreSQL, Full-Stack Microservice).

## 5. Model Context Protocol (MCP) Server (`cf mcp`, `internal/mcp`)

Full 13-tool stdio interface enabling AI coding agents to inspect schemas, build compositions, and verify outputs:

- `list_kinds`, `get_kind_fields`, `get_blueprint`, `replace_blueprint`, `add_parameter`, `update_parameter`, `rename_parameter`, `delete_parameter`, `add_provider`, `list_providers`, `generate`, `render_check`, `adopt_composition`.
- Strict workspace confinement ensuring agents can only modify designated blueprint files and output directories.
