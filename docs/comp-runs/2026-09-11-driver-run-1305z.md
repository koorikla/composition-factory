## Operational Observations & Reverted Items

1. **CF-236 Reversion and The Round-Trip Rule (`AGENTS.md` §1)**:
   - Early in the session, an attempt was made on CF-236 (`91ffaee`) to record a loss report warning when adopting a composition without `functions.yaml` and assuming default `function-auto-ready`.
   - However, in cluster round-trips (`cf gen` -> `kubectl apply` -> `kubectl get -o yaml` -> `cf import`), live clusters export only `definition.yaml` and `composition.yaml` without `functions.yaml`.
   - Recording an unrecovered function package in `LossReport` flagged loss and caused `cf import` to exit 2, breaking Lane C in-cluster verification (`scripts/cluster/test-cluster.sh`) and `tests/cf217-import-xrd-lossless.spec.js`.
   - Commit `91ffaee` was reverted via `3292574` to preserve `main` greenness, and the architectural trade-off was documented on issue #131.

2. **Test Flakiness Root-Caused and Fixed (`tests/cf235-toast-stacking.spec.js`)**:
   - In CF-249, pruning unknown wired fields allowed `store.generate(false)` to succeed on import.
   - However, `web-proto/js/main.js:181-183` registered `store.subscribe("generate", () => clearErrorToast())`.
   - The asynchronous debounced generate preview call resolved a few hundred milliseconds after import, clearing the simulated error toast while Playwright asserted on it.
   - By explicitly awaiting the background generate preview completion (`waitForResponse('/api/generate')`) prior to triggering the test error, the race condition was completely eliminated (`bd64218`), making the test 100% deterministic in CI.

3. **Strict Linting Enforcement**:
   - During CF-250 merge, staticcheck detected an unused field `closeErr` in `internal/mcp/transport.go`, failing `make lint-strict`.
   - The unused field was removed immediately in `2376c45`, followed by clean CI run [34620240194](https://github.com/koorikla/composition-factory/actions/runs/34620240194) with all 5 CI jobs green.
