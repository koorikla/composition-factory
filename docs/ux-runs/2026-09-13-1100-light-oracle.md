intact: bind a status-only string to an annotation on another resource.

**The run.** Blank document → the Starter Blueprints modal (`#examplesOverlay`) opens; closing
it with `#examplesCloseBtn` works and it stays closed. Dropped `Bucket` and `ServiceAccount`
from the palette. Dragged the Bucket card's `status.atProvider.arn` port onto the
ServiceAccount card. Then Generate.

Against M2's oracle, the canvas did well on every point:

- **A status field is a source, visibly.** The Bucket card exposes its status fields as ports
  directly on the card — `["region","status.atProvider.id","status.atProvider.accelerationStatus","status.atProvider.acl","status.atProvider.arn","status.atProvider.bucketDomainName","status.atProvider.bucketNamespace"]`.
  Nothing has to be known in advance; you drag the one you want.
- **Dropping onto an annotation is discoverable.** The drop opens a picker headed
  `Wire bucket.atProvider.arn → service-account`, with categories
  `["Suggested Matches","Spec Fields"]`. Among 17 items it offers, unprompted:

  ```
  annotations.eks.amazonaws.com/role-arn   string   EKS IAM Role ARN to assume
  annotations.crossplane.io/external-name  string   Cloud resource name override
  ```

  So the exact IRSA annotation this mission wants is a named, described suggestion — the user
  never has to know the `annotations:` block grammar. The picker also type-checks: the
  whole-map `metadata.annotations` entry is shown greyed with `mismatch: string ≠ map`.
- **The wire is guarded, without being asked.** Picking the suggestion wrote
  `{"eks.amazonaws.com/role-arn":{"from":"resources.bucket.status.atProvider.arn"}}`, and
  `cf gen` emitted the binding already guarded on the status being observed:

  ```
              {{- if hasKey (dig "resources" "bucket" "resource" "status" "atProvider" dict $.observed) "arn" }}
                'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "bucket").resource.status.atProvider.arn | quote }}
              {{- end }}
  ```
- **The dependency is laid out.** After the wire, the cards sit `xrd` x=352, `bucket` x=610,
  `service-account` x=908 — the source precedes the dependent left to right.
- **The wire reads.** It is drawn with its own `wire-path wire-status` class, and the bound
  annotation row reads
  `eks.amazonaws.com/role-arn ← resources.bucket.status.atProvider.arn` with the full binding
  `bucket.status.atProvider.arn → service-account.annotations.eks.amazonaws.com/role-arn`
  as its title.
- **Generate.** `#generateBtn` names the real output directory in its tooltip, confirms with
  *"Generate will write manifests to disk in '…/m2b/out'. Proceed?"*, and on accept writes four
  files: `compositions/xapps.platform.example.org.yaml`, `xrds/…`, `functions.yaml`,
  `providerconfigs/aws.yaml`. Validate is "unavailable" here — no Docker (CF-093).
