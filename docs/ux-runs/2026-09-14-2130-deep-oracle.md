### M1 — First contact: an S3 bucket, from nothing — *completed*, ~14 min to Generate

Searching the palette for `s3` surfaces `Bucket` under `S3.AWS.M.UPBOUND.IO` with
`NAMESPACED (V2) · MATCHES XRD` and `1 req` — the word a user knows, the kind they want, and
an honest count of what is still required. Dragging it onto the canvas worked first time.

Wiring the region parameter took three routes before one landed, and the route that worked is
the discoverable one:

1. `+ Add parameter` on the XRD creates a row pre-named **`newParam`**, which you then rename.
2. The field's own `Wire` button opens a source list that already offers
   `params.providerName` and — the good affordance — **`+ new XRD parameter…`**.
3. Choosing that opens an inline form with a `parameterName` box and an **`Add`** button.
   Typing the name and pressing Enter does nothing; clicking `Add` completes the wire.

The Enter-vs-Add gap is real friction but is not filed: a scripted driver cannot distinguish
"Enter is not bound" from its own synthetic keystroke failing to reach the handler, and that
distinction is the whole finding. Flagged for a human-driven run.

Oracle met. The XRD declares the parameter with its type:

```yaml
              region:
                type: string
            required: [providerName]
```

and the Composition sources the Bucket's region from it instead of the literal it started
with (`region: 'us-east-1'` before the wire):

```
{{- if or (hasKey $spec "region") }}
{{- if hasKey $spec "region" }}
region: {{ $spec.region | quote }}
```

The canvas put a `⚠` on the Bucket node at that point: `region` is a *required* provider
field now fed by an *optional* XRD parameter, so the emitted resource is guarded by `hasKey`
and will simply lack its required field if the parameter is omitted. That is exactly
**CF-493** (#407, open and already handed back to a driver) — the canvas warns, `cf gen` does
not. Independent corroboration of that issue from a second path; not re-filed.

## 7. A driver artifact, recorded so it is not re-filed

For roughly fifteen minutes this run held what looked like a P0: clicking **Generate**
produced no files, no dialog, no toast, and — verified against a response listener that saw
`200 POST /api/render` from Validate moments earlier — **zero** API requests, across four
clicks and three engine sessions, while the banner read "Preview only · Click Generate to
write to …".

It is not a defect. `generateNow` (`web-proto/js/regions/output.js:912-924`) calls
`window.confirm`, and Playwright auto-dismisses dialogs unless the driver accepts them.
With a `dialog` handler attached, the same click yields `200 POST /api/generate` and writes
all five artifacts. Any future scripted run of this canvas needs that handler; without it,
Generate is silently a no-op and looks exactly like a catastrophic bug.
