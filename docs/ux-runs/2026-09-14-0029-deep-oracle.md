## 4. Mission M3 — connection secret: RDS PostgreSQL

**Outcome: blocked on its own resource, completed with a workaround on the
subject it measures.** Blank start, 00:33 → 00:45.

Finding a Postgres provider was easy and the search is better than the mission
feared: typing `postgres` into the SOURCES catalogue returns
`provider-azure-dbforpostgresql`, `provider-aws-rds` and `provider-gcp-sql`,
with `provider-aws-rds` reached by description rather than package name. That is
the thing CF-142 was filed for and it works.

Adding it does not, here: the sandbox denies the ghcr blob CDN, so `Add` fails
with a 502 from `/api/providers` and the panel shows the registry error. That is
#68 (no seeded RDS schema), not a finding — but *how* that error is shown is
(CF-492 below).

With no RDS kinds, I carried the mission's real question — is the
connection-secret envelope findable without knowing the word "envelope"? — to
the managed kinds the cache does have.

- On the **XR** card: `Environment`, `PARAMETERS`, `PIPELINE`. Nothing about
  connection secrets. The `Manifest`/`Fields` toggle and the `search fields…`
  box are both rendered for the XR and both do nothing there.
- On a **native** kind (StatefulSet): `FOR EACH`, `WHEN`, `ESSENTIALS`,
  `MANIFEST`, `NAMING & METADATA PRESETS`, `ANNOTATIONS`, `STATUS OUTPUTS`.
  Still nothing — correctly, a StatefulSet has no connection secret.
- On a **managed** kind (SQS `Queue`): a `CROSSPLANE ENVELOPE` section appears,
  subtitled *"Secrets, policies and metadata outside forProvider"*, carrying
  `writeConnectionSecretToRef.name`.

So the envelope **is** discoverable once a managed resource is selected, and the
subtitle carries the word "Secrets" so you do not have to know "envelope". That
is a good answer to M3's question and the run's clearest win. What is wrong is
the state that row is shown in — see CF-488.

The mission's second question — does anything warn when a secret-shaped field is
typed in plain — answers "no". Adding an environment variable
`POSTGRES_PASSWORD` = `hunter2-plaintext` on the StatefulSet draws no warning at
any point, and Generate emits it verbatim:

```yaml
                      - name: 'POSTGRES_PASSWORD'
                        value: 'hunter2-plaintext'
```

**Not filed.** The user typed that value deliberately and the tool emitted what
was typed; a warning here is a feature wish, not a defect. It is recorded
because CF-474 and CF-476 were the same shape with the starter as the author,
and because the next tester should not have to rediscover that the general
surface is unguarded.

## 5. Mission M1 — first contact: an S3 bucket, from nothing

**Outcome: completed** (to Generate; Validate is unavailable, CF-093).
Blank start 00:45 → generated 00:47:46, three scripted minutes.

The seeded cache changes first contact: S3 kinds are already in the KINDS
palette on arrival, so the mission's "find a provider" step is skipped. Noted so

The starter-blueprint chooser opens by itself on a blank document. `Escape`
closes it and so does its `×`; both verified. It is the first thing a new user
sees and it is a reasonable thing to show.

Palette search is good: `s3` and `bucket` both surface `Bucket` at the top of
`S3.AWS.M.UPBOUND.IO`. Clicking a kind drops it on the canvas.

Wiring the parameter took the `Wire` button on the `REGION` essentials row,
whose dropdown offers `wire to…` / `params.providerName` / `+ new XRD
parameter…`. Choosing the last opens an inline name field; typing `region` and
pressing `Add` both creates the parameter and completes the wire in one step.
One wire drawn, blueprint written:

```yaml
  resources:
  - fields:
      region:
        from: params.region
    kind: Bucket
```

and the emitted XRD declares it with its type:

```yaml
              region:
                type: string
            required: [providerName]
```

Mission oracle met. Validate reports `validation check unavailable` (Docker).

**Round trip.** `Import` on the exported
`compositions/xapps.platform.example.org.yaml` confirms first with *"Import will
replace bucket.cf.yaml (undoable)"*, then restores `XApp` with two parameters
and the `Bucket` with its wire — intact. The only difference is
`providerName`'s `description`, which the adopt path synthesises because a
Composition does not carry XRD parameter descriptions at all. Not a loss.

Two smaller observations, neither filed:

- The `↗ param` one-click expose-as-parameter button sits on native-kind
  essentials rows (`REPLICAS`, `IMAGE`, `PORT`, `CPU REQUEST`) but not on
  managed-resource rows — `Bucket.REGION` and `Queue.REGION` show only
  `Val`/`Wire`/`Raw`. The `Wire` → `+ new XRD parameter…` path reaches the same
  result in one extra click, so this is an inconsistency rather than a gap.
- The card's warning glyph on a wired required field is excellent: hovering
  `region ⚠` reads *"Optional parameter wired to required field: render will
  omit if missing"*, which is exactly the failure mode and exactly when to say
  it.

Ten minutes, and nothing to file: this area is in good shape.

- Loading `AWS S3 Secure Storage Bucket` from the chooser replaces the document
  with 4 resources; loading `AWS SQS Queue with Dead Letter Queue` over it gives
  4 more. `↩` restores the previous document exactly and `↪` puts it back.

  ```

  messageRetentionSeconds, region. Downstream references in queue-policy
  ```

  Wire count 7 → 3 on the delete, and `↩` restores all 7 **and** the resource.
- Undo does put the restored resource last in the document order rather than

  after (`diff` of two Generate runs: 0 lines), so the ordering is normalised

  chooser promised "undoable". Expected for browser-held history; recorded only
  so the next tester does not mistake it for the chooser failing to record.

## 8. What worked

- The starter chooser, undo/redo and the delete confirmation are the best part
  of the canvas right now. The delete dialog naming the downstream resource and
  field it will unwire is the kind of thing a user only notices by its absence.
- `Wire` → `+ new XRD parameter…` turns M1's central step into two clicks and a
  word, and it leaves both the parameter and the wire correct.
- The `⚠` on a required field wired to an optional parameter states the exact
  render-time consequence.
- Both catalogue search and palette search find things by the words a user
  knows — `postgres` finds RDS, `s3` and `bucket` both find `Bucket`.
- Zero uncaught page errors across every phase of both missions and the extra
  area. The console rule found nothing, which is worth saying out loud.
