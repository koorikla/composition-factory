## 6. Two candidates examined and deliberately not filed

Recorded so the next run does not spend time re-deriving them.

**`Generate` appeared to do nothing.** Clicking `#generateBtn` fired zero `/api/` calls
and wrote no files. The cause was my own harness: `Generate` raises a
`window.confirm` (`"Generate will write manifests to disk in '…'. Proceed?"`) and
Playwright auto-dismisses dialogs unless a handler is registered. With
`page.on('dialog', d => d.accept())` it posts `200 POST /api/generate` and writes
correctly. A driver artefact, not a product defect.

**The envelope row looked like it had no input.** `writeConnectionSecretToRef.name` shows
`Val` as `aria-pressed="true"` while its `nextElementSibling` is only the description
`<div class="fld-d">Name of the secret.</div>`. The input exists
(`input[data-env-v="writeConnectionSecretToRef.name"]`, placeholder
`unset — omitted from envelope`); it is simply not the immediate sibling. My selector was
wrong, and the row behaves the same way as `managementPolicies` and
`providerConfigRef.name`.

One further observation, left unfiled as a style matter rather than a defect: the emitted
guard for a single optional field is `{{- if or (hasKey $spec "region") }}` wrapping an
identical inner `{{- if hasKey $spec "region" }}`. `or` with one argument is redundant,
but the output is correct and deterministic, which puts it outside the evidence bar.
