## 4. Missions

### M1 — First contact: an S3 bucket, from nothing — **completed** (Validate unavailable)

Time to Generate: roughly 25 minutes of driver time, most of it my own scripting overhead
rather than the product's.

On arrival at a blank canvas the **Examples chooser opens over the canvas**. It is
dismissible with Escape and it is genuinely informative — seven starters, each with a
resource count and a provider-dependency badge — but it is what a first-time visitor
meets before they see the canvas at all. I closed it and went to the palette.

Searching the palette for `s3` — the word a user knows, not the package name — works:
25 `s3.aws.m.upbound.io` kinds, `Bucket` first, each tooltipped with its full apiVersion
and originating provider. The palette entries are `role="button"` with
`aria-label="Add Bucket"`, and a plain click adds the card; drag is not the only route in.

Adding the `region` parameter took: select the XRD card → `+ Add parameter` → rename
`newParam` to `region`. Wiring it took: select Bucket → `Wire` on the `region` row → pick
from a `wire to…` dropdown that lists `params.region (optional → req)`. That annotation is
a good touch, and after wiring the inspector shows a standing
`⚠ optional param into required field` notice. The warning is real and visible, so the
resulting XRD (`required: [providerName]` only) is a disclosed trade-off, not a silent one.
Generated output meets the oracle:

```yaml
{{- if or (hasKey $spec "region") }}
{{- if hasKey $spec "region" }}
region: {{ $spec.region | quote }}
{{- end }}
{{- else }}
{}
{{- end }}
```

and the XRD declares `region: {type: string}`. **Validate reads "validation check
unavailable"** — `crossplane CLI not found on PATH` — which is CF-093 / no Docker here, so
per the standing rule the mission stops at Generate and `cf gen` output is the oracle.

**Round-trip: clean.** Re-importing the exported Composition *and* XRD through the UI file
picker produced a blueprint **byte-identical** to the pre-export one — same two resources,
same `region: {from: params.region}` wire, same parameters — and the canvas came back with
`nodes: [xrd, bucket]`, `wires: 1`.

## 5. Leads chased and dropped

Both are recorded because a later run will otherwise re-chase them.

**A map entry that would not persist.** Typing a key/value into a `Secret`'s `stringData`
and pressing Tab or Enter fired no request and left `fields: {}`; a control edit
(`immutable` → `true`) fired `200 PUT blueprint` and landed immediately, which looked like
a broken map widget. It is not: the row is
`<input data-new-map-key> <input data-new-map-val> <button data-new-map-ok>Add</button>`,
and clicking **Add** commits correctly. My driving was wrong, not the widget. (Enter does
not activate that Add button; that is polish, not a defect, and not filed.)

**Generate appearing to do nothing.** `#generateBtn` produced no API call and wrote no
files across three attempts. Cause: Generate raises a native
`confirm("Generate will write manifests to disk in '.testrun-ux/out'. Proceed?")`, and
Playwright auto-dismisses native dialogs unless a handler accepts them. With a handler
attached, `POST /api/generate` fires and all four artifacts are written. A scripted-driver
artifact, not a product defect — worth knowing for whoever writes the next driver.
