**This is exactly where the missing schemas stop M2**, and it is CF-183 (#68) / the egress
policy — not filed. The mission's *mechanic* — a native `ServiceAccount` whose annotation is
bound to a managed resource's observed status, guarded — was run in full with the only
status-bearing managed kind available, `sqs.Queue`, standing in for the IAM Role.

Blank start → dismissed the Examples modal → `#psearch` "ServiceAccount" → dragged it onto
the canvas → "Queue" → dragged. The engine added `providerName` to the XRD by itself.

**What the canvas did well, judged cold:**

- The Annotations row's value placeholder reads **`value (or placeholder to wire)`** — that
  is where a first-time user learns an annotation can be a wire at all.
- Adding a key with no value **refuses loudly**, with a toast and a warnbar:
  `Annotation "eks.amazonaws.com/role-arn" requires a value (or …)`. Nothing is silently dropped.
- Once added, the annotation carries a **Val / Wire / Raw** control
  (`title="Wire from a parameter or resource status"`) — CF-478's surface, and it is discoverable.
- The wire dropdown lists the status fields directly, so "a status field can be a source"
  needs no prior knowledge:

```
resources.queue.status.atProvider.arn | resources.queue.status.atProvider.arn
resources.queue.status.atProvider.url | resources.queue.status.atProvider.url
resources.queue.status.lastHandledReconcileAt | …
```

- **The guard appeared without being asked for.** Selecting the ARN produced, at Generate,
  the CF-481/CF-482 resource-level gate wrapping the whole `ServiceAccount`.

**Oracle:** annotation bound to `status.atProvider.arn` ✅; binding guarded ✅; Validate —
**unavailable**, Docker absent (CF-093), so `cf gen` and the emitted YAML were the oracle.

**Round-trip (the mission's closing step): byte-perfect.**

```sh
{ cat gen1/xrds/*.yaml; echo "---"; cat gen1/compositions/*.yaml; } > combined2.yaml
./bin/cf adopt combined2.yaml -o readopted2.cf.yaml --cache-dir $S/cache
diff <(grep -v "^#" irsa.cf.yaml) <(grep -v "^#" readopted2.cf.yaml)   # IDENTICAL
./bin/cf gen readopted2.cf.yaml --out gen2 && diff -r gen1 gen2        # REGEN BYTE-IDENTICAL
```

The annotation status wire survives import intact.

**One ordering note, deliberately not filed.** The `ServiceAccount` is emitted *before* the
`Queue` it depends on, whereas M2's oracle wants the producer laid down first. Under
go-templating both objects are rendered in one pass and the CF-481 gate — not document order —
is what sequences creation, so this costs nothing at runtime and is a readability preference,
not a moment where the tool did the wrong thing.

**A false lead, recorded so it is not chased again.** `cat xrd.yaml composition.yaml` **without**
a `---` separator makes one malformed document; `cf adopt` then reports
`xrd.parameters.<name>: without the XRD, default, enum and description could not be recovered`
and substitutes a canned description. That is correct handling of bad input, not a round-trip
drop — with the separator present, every `default`, `enum` and `description` round-trips and
the loss report is empty. This looked like a P1 silent-substitution finding for several minutes.

### M3 — Connection secret: RDS PostgreSQL · **blocked at load**, substituted, no new defect


The card turns red (`example-card has-error`), a toast repeats the reason, and
`/api/blueprint` still returns `resources: []` — **the failed load leaves the document
untouched rather than half-applied.** This is where the missing schemas stop M3; #68, not filed.

Substituted the **Cloud-Agnostic Portable Database** starter, which is the same user goal
(a Postgres whose credentials reach the requesting app as a Secret) on native kinds only. It
loads cleanly: `db-secret`, `db-service`, `db-statefulset`, no warnings.

**Oracle, honestly:**

- *Connection-secret envelope* — **not reachable on this path.** `writeConnectionSecretToRef`
  is a schema field of a managed resource, not a native-kind feature; a `StatefulSet` has
  none. The envelope needs RDS, so this clause of M3 went unexercised here. The envelope's
  own UX is already open as CF-484 (#396) and CF-488 (#401).
- *The password never appears as a literal in the Composition* — **holds.** CF-474/CF-476 are
  genuinely fixed: `password` is gone from the XRD, and the template reads
  `POSTGRES_PASSWORD: {{ $env.password | quote }}`.
- *Validate green* — unavailable (CF-093).

**Where the credential actually lives, and what the canvas says about it.** Two `cf gen` runs,
byte-identical:

```yaml
# out/environmentconfigs/default.yaml
apiVersion: apiextensions.crossplane.io/v1beta1
kind: EnvironmentConfig
metadata:
  name: default
data:
  password: ""
```

`internal/emit/environment_config.go:35-52` writes **every** `spec.environment` key into a plain
`EnvironmentConfig`'s `data:` map; there is no secret-typed environment key, and the object name
defaults to `default` (`:20`) for every blueprint. So the master password's only slot is a
non-Secret object shared by default. Searching the whole rendered canvas, the only warning
language anywhere near it is the inspector's neutral `Secret data vs stringData:` note on
`db-secret`; nothing on the parameter, the wire, or the output pane says the value is stored
in plain. `cf gen` prints only the unrelated RBAC warning.

This is **already inside CF-487 (#400)**, whose contract says "the emitted artifact must stop
presenting itself as the place to type one — and in that case the blueprint, the starter and
the canvas must name the place that is". Rather than re-file, the evidence above was added to
#400 as a comment.
