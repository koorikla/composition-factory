### M2 — The status wire (IRSA shape) · blank start → Generate · **completed**

IAM `Role` unavailable, so the status source is the cached SQS `Queue`, which carries
`status.atProvider.arn` — the same status-field-into-an-annotation binding IRSA needs.
Target is a native `ServiceAccount` with `eks.amazonaws.com/role-arn`, as written.

Time to Generate: ~9 min of driving. Console clean at every phase.

What the mission asked to watch:

- **How you learn a status field can be a source at all.** Immediately and without being
  told. The `Queue` card renders an `outputs` section listing `name / id`, `arn`,
  `contentBasedDeduplication`, … each with its own port. Selecting the resource also gives
  the Inspector a `STATUS OUTPUTS` block headed *"Other resources can wire from this
  object's status:"*. Nothing here requires prior knowledge.
- **Whether dragging onto an annotation is discoverable.** The Inspector's `ANNOTATIONS`
  row carries a `Val | Wire | Raw` toggle (CF-478's fix). `Wire` swaps the value box for a
  `wire to…` dropdown that lists every status field by path, including
  `resources.queue.status.atProvider.arn`. One click, no guessing.
- **One piece of friction, correctly signposted.** An annotation cannot be created empty:

  ```
  ⚠ Annotation "eks.amazonaws.com/role-arn" requires a value (or a temporary placeholder to wire later)
  ```

  So wiring a status output into a *new* annotation costs one throwaway keystroke first.
  The message names the workaround in its own text, and the placeholder leaves no residue —
  after wiring, the blueprint holds `from:` with no trace of the typed value. Loud, cheap,
  self-explaining: friction, not a defect.
- **Whether the guard appears without asking.** It does, twice over.

Blueprint after wiring:

```yaml
  - annotations:
      eks.amazonaws.com/role-arn:
        from: resources.queue.status.atProvider.arn
    fields: {}
    kind: ServiceAccount
    name: service-account
    provider: k8s
```

Emitted Composition — the whole `ServiceAccount` is gated on the ARN existing (CF-482's
fix) *and* the annotation is independently guarded:

```
          {{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
          ---
          apiVersion: v1
          kind: ServiceAccount
          metadata:
            name: {{ $xr }}-service-account
            annotations:
              {{ setResourceNameAnnotation "service-account" }}
              {{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
              'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "queue").resource.status.atProvider.arn | quote }}
              {{- end }}
          {{- end }}
```

**Oracle met**: annotation bound to the status field ✓, binding guarded ✓, `Queue` emitted
before `ServiceAccount` and auto-laid left-to-right on the canvas with a readable green
status wire ✓ (`m2/gen2.png`). Validate unavailable (CF-093).

One thing checked and found **correct, not a defect**: the run wrote no `rbac.yaml` and
printed no RBAC warning despite composing a native kind. `internal/emit/rbac.go:14`
lists `ServiceAccount` in `preGrantedNativeKinds` — Crossplane's default aggregate
ClusterRole already covers it. The M3 blueprint, which composes a `StatefulSet` (not
pre-granted), *did* get an `rbac.yaml`. The rule is applied correctly in both directions.
