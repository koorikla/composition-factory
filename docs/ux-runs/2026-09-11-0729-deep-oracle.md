### M1 — First contact: an S3 bucket, from nothing — **completed**, ~4 min to Generate

Blank scaffold → `s3` in the kinds search → drag `Bucket` (namespaced v2) onto the canvas →
`Wire` on `region` → `+ new XRD parameter…` → name it `region` → `Add`.

Everything on that path worked first time. The drop declared the source by itself
(`ghcr.io/crossplane-contrib/provider-aws-s3:v2.7.0` appeared in `spec.sources` without a visit
to SOURCES). The `req` checkbox on the new-parameter form arrives checked, so `region` landed

region]` and the composition body reads `region: {{ $spec.region | quote }}`.

Validate answers `validation check unavailable` (CF-093, no Docker). Mission oracle is otherwise
met; Generate wrote 4 files.

Round-trip: importing the exported `composition.yaml` alone reproduced the resource, the wire
and `region: {type: string, required: true}` intact. The only drift was `providerName`'s
description, rewritten to the scaffold's own wording — reported in the change banner.

*Watch-for notes.* Arrival copy is helpful and non-blocking. `s3` finds the family by the word a
user knows. The first drag is discoverable — the hint names it. The kind tooltip lingers after
the drop (already CF-159, #44).

### M2 — The status wire — **completed with a substitution**, ~6 min to Generate

`provider-aws-iam` cannot be fetched here, so the IRSA shape was built with the cached SQS
provider: `Queue.status.atProvider.arn` → a `ServiceAccount`'s
`eks.amazonaws.com/role-arn` annotation. The mechanism under test — a status field as a wire
source, dropped onto an annotation rather than a spec field — is the same.

Adding the provider from the catalogue's `Add` button worked off the seeded cache (7.6 s, no
spinner needed). The annotation had to exist before it could be a wire target: the inspector's
ANNOTATIONS form creates the key, and only then does the ServiceAccount card grow an
`annotations` port you can drop onto. That ordering is not stated anywhere, but the empty-value
refusal (CF-136) points at it: *"or a temporary placeholder to wire later"*.

Dragging `arn`'s output dot onto that port bound it immediately. The emitted template is exactly
what the mission asks for — guard included, without being asked:

```yaml
          apiVersion: v1
          kind: ServiceAccount
          metadata:
            name: {{ $xr }}-service-account
            annotations:
              {{ setResourceNameAnnotation "service-account" }}
              {{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
              'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "queue").resource.status.atProvider.arn | quote }}
              {{- end }}
```

Queue precedes ServiceAccount in the rendered order. Round-trip: re-importing the generated
Composition reproduced both resources and the annotation binding **byte-identically**.

*Watch-for notes.* You learn a status field can be a source from the `outputs` group on the
source card, which lists status leaves with their own dots — it reads well. The wire itself is
readable on the canvas but its binding text is truncated in the inspector (already CF-139, #24).
The inspector renders the annotation key in **uppercase**, which for a case-sensitive Kubernetes
key is wrong — CF-192.

set, and Generate wrote `forProvider: {}` under a green `written · 4 files · 3 previews`.

### CF-190 (P2, ux) — related to CF-108 (#6) and CF-119 (#7)

Load the `Cloud-Agnostic Web Workload` starter, Generate, re-import the Composition the UI just
wrote. The loss banner is detailed and itemised — and omits the one change that alters the XRD
contract:

- before: `enableService: {type: boolean, required: false, default: "true", description: …}`
- after: `enableService: {type: boolean, required: true}`
- banner: *"adopted with 5 dropped items: xrd.parameters.enableService (without the XRD, default,
  enum and description could not be recovered); …"* — the word `required` never appears.

The change is forced (the `when:` condition dereferences the key unguarded, and without the
recovered default the emitter would refuse), but the consequence is a contract change:
`required: [image, providerName]` becomes `required: [enableService, image, providerName]`, and
every existing XR that relied on the default now fails admission. Reproduced twice.

## 7. What worked

Worth naming, because a run that only lists complaints cannot be calibrated.

- **The guard came for free.** Nobody asked for `hasKey`/`dig`; the status→annotation wire
  emitted it, correctly nested, on the first try.
- **The loss report.** Import names what it could not recover, item by item, with an Undo link
  beside it. CF-190 is a gap *in* a good report, not the absence of one.
- **Undo is trustworthy.** It survives a starter load, a wired-resource delete and a redo, and
  it restores wires, not just cards.
- **Dropping a kind declares its source.** M1 never had to open SOURCES.
- **The catalogue dead-end is gone.** A search with no hits now offers the providers that would
  satisfy it, with one-click `Add`.
