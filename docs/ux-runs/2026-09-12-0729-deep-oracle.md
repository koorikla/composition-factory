## 5. M2 — the status wire

**Outcome: completed.** ~22 min from blank canvas to Generate writing 4 files. Validate
unavailable (CF-093), so the oracle used was `cf gen` output per the run prompt.

Substitution: `Queue.status.atProvider.arn` → `ServiceAccount` annotation
`eks.amazonaws.com/role-arn`, instead of `Role.status.atProvider.arn`.

### Narrative

Arrival puts a **starter chooser modal over the whole canvas** before you have done anything.
It is well-built — six starters, each with a resource count and a `ready` / `↓ 1 provider`
badge — and one of them is literally *"AWS IRSA (IAM Role + EKS ServiceAccount)"*, which is
this mission. Taking the tool at its word and clicking **Load Blueprint** was the obvious first
move. It failed, and it failed **well**: a red toast naming the exact package and reason
(`failed to cache provider: unable to fetch source "ghcr.io/crossplane-contrib/provider-aws-iam:v2.7.0" … Forbidden`),
with every credential in the signed URL redacted. Critically, **the document was left
untouched** — `spec.resources: []`, `spec.sources: []`, blank canvas. A starter that cannot
finish does not half-apply. That is the right behaviour and worth keeping.

Closing the chooser (Escape works) and searching KINDS for `Queue` was the next move, and here
the run hit its one blocker — see the finding below: the palette had silently lost every cached
provider kind, showing only the 16 native Kubernetes kinds and the message *"No kinds match
search query. Add a provider in SOURCES."* On a fresh engine the same search offers `Queue`
immediately. Restarting the engine and dragging `Queue` as the **first** action worked.

From there the mission ran clean:

- Dragging `Queue` (the `NAMESPACED (V2)` variant — the palette offers both it and the
  cluster-scoped legacy one, labelled clearly) and `ServiceAccount` onto the canvas both worked
  first try.
- **How you learn a status field can be a source**: the Inspector has an explicit
  **`STATUS OUTPUTS`** section — *"Other resources can wire from this object's status"* — listing
  `status.atProvider.arn` and siblings, and the node itself grows an `outputs` block with a port
  per status field. This is genuinely discoverable; no source-reading required.
- **Dragging onto an annotation** is discoverable *after* the annotation exists. The Inspector's
  `ANNOTATIONS` row (`prefix/name` + `value (or placeholder to wire)` + `Add`) creates it, and
  the node immediately grows an input port for it. Wiring `arn` → that port drew a teal
  `wire-status` wire and produced `from: resources.queue.status.atProvider.arn`.
- **The guard appears without being asked for.** Generated Composition:

```yaml
          apiVersion: v1
          kind: ServiceAccount
          metadata:
            name: {{ $xr }}-service-account
            annotations:
              {{ setResourceNameAnnotation "service-account" }}
              {{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
              'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "queue").resource.status.atProvider.arn | quote }}
              {{- end }}
```

- **Ordering** reads correctly: the Queue card sits left of the ServiceAccount with the wire
  running between them.
- **Generate.** `write:false` (preview) is continuous; the button itself raises a
  `confirm()` — *"Generate will write manifests to disk in '…/out'. Proceed?"* — and then
  `POST /api/generate {"write":true}`. With `region` unset this returns **400**
  (`resource "queue": missing required field "region" in Queue spec.forProvider`) and the status
  chip reads `error`; after setting `region: eu-west-1` through the Inspector it reads
  `written · 4 files · 3 previews` and four files land on disk.

## 6. M3 — connection secret

- **Is the envelope findable without knowing the word "envelope"?** Partly — the Inspector

```yaml

              name: 'queue-conn'
```

  the ref.

  typed in plain?*) **could not be answered** — SQS has no password-shaped field. That part of
  M3 needs an RDS or equivalent schema in the seeded cache.

### Finding 1 — cached provider kinds vanish after one save (open issue #235)

Not re-filed: this is exactly open **CF-345 (#235)**. Recorded here because the repro is sharper
than the issue's and because it **blocks every blank-start mission** in this environment — the
kinds a mission needs disappear before the mission's second action.

Reproduced twice, deterministically, on `main`@`91e1bfd`:

```
$ ./bin/cf serve --addr 127.0.0.1:19310 --blueprint <missing> --cache-dir <seeded cache>
$ curl -s "…/api/kinds?q=queue" | …   →  8 queue kinds          # fresh start
$ curl -s -X PUT …/api/blueprint  (rename XRD kind only)   →  PUT=200
$ curl -s "…/api/kinds?q=queue" | …   →  0 queue kinds          # after ONE save
```

`spec.sources` is `[]` before and after; only the XRD `kind`/`plural` changed. In the canvas
this surfaces as the KINDS palette dropping to the 16 native kinds and answering
*"No kinds match search query. Add a provider in SOURCES."* for `Queue`, `Bucket` and `sqs`
alike. A page reload does not restore them. Once a resource from the provider is on the canvas
(so `spec.sources` is non-empty) the palette repopulates, which is why the defect is invisible
to anyone who is not starting from blank.

### Finding 2 — dead status port on native kinds (CF-413)

Every native (non-managed) kind renders an `outputs` block with a `status.atProvider.id` port
labelled **`name / id`**. `ServiceAccount`, `ConfigMap`, `Secret` and `Service` all show it.
Dragging from it is always refused, at both layers:

```
HTTP 400 PUT /api/blueprint -> {"error":"resource \"queue\" field \"region\": kind
\"ServiceAccount\" declares no status schema in its CRD, so
resources.service-account.status.atProvider.id can never carry a value"}
```

```
$ ./bin/cf gen native-status.cf.yaml
cf: error: resource "cm" annotation "example.com/sa-id": kind "ServiceAccount" declares no
status schema in its CRD; nothing can be wired from resource "sa"'s status
```

The refusal is loud and the document is not corrupted — this is not silent harm. The cost is the
affordance itself: `name / id` is the label for a thing users genuinely want (wire a ConfigMap's
name into a Deployment), the canvas offers a port for it on every native card, and the only path
it offers can never carry a value.

## 9. What worked

Worth naming, because a run that only lists complaints cannot be calibrated:

- **Atomic starter failure.** A provider fetch that cannot complete leaves the document exactly
  as it was, and says why, with credentials redacted out of the signed URL.
- **`STATUS OUTPUTS` as a first-class Inspector section.** The mission's hardest question — *how
  do you learn a status field can be a source at all?* — is answered by the panel, not by the docs.
- **The guard is automatic.** No user action produced the `hasKey (dig …)` wrapper; the emitter
  added it. M2's oracle asks for a guarded binding and the tool simply does it.
- **Required fields fail closed on write.** Preview is permissive, but `write:true` refuses a
  blueprint missing `region` with the resource, the field and the reason all named.
- **Loss on re-import is reported.** `adopted with 1 dropped item: pipeline.auto-ready …` — named,
  with the reason.
- **Error copy is unusually good throughout** — every refusal this run produced named the
  resource, the field, the reason, and often the fix.
