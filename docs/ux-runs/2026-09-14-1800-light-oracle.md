## 3. Mission M3 — connection secret, RDS PostgreSQL

Blank start on port 19320, stopped at Generate (Validate reads unavailable, Docker absent, CF-093).

**Where the missing schemas stop the mission.** The Examples chooser opens by itself on a blank
start, and its RDS card is honest about the cost before you click: the badge `↓ 1 provider`
carries `title="Downloads on load: ghcr.io/crossplane-contrib/provider-aws-rds:v2.7.0"`. Loading
it fails loudly and keeps the chooser open:

```
⚠️ failed to cache provider: unable to fetch source "ghcr.io/crossplane-contrib/provider-aws-rds:v2.7.0":
   read image config: Get "https://pkg-containers.githubusercontent.com/ghcrblobs11/blobs/sha256:604c...": Forbidden
```

That is the environment's denied ghcr blob CDN (#68), not a finding. The warning names the
provider, the layer and the HTTP verdict — a user on a real network would know what to retry.

**The mission run as far as native kinds allow.** The chooser's `DB — Cloud-Agnostic Portable
Database` starter is the zero-dependency path to the same oracle: a PostgreSQL whose credentials
reach the requesting app as a Secret. It loaded clean — `XDatabase`, `EnvironmentConfig`,
`Secret`, `Service`, `StatefulSet`, no console errors — and Generate wrote five files.

**Oracle: the password never appears as a literal in the Composition.** It does not. Every
reference is indirect:

```
compositions/xdatabases.database.sparky.ee.yaml:9:    factory.crossplane.io/environment-keys: '{"password":{"type":"string","description":"Master password for PostgreSQL."}}'
compositions/xdatabases.database.sparky.ee.yaml:48:          {{- if or (hasKey $spec "dbName") (hasKey $env "password") (hasKey $spec "username") }}
compositions/xdatabases.database.sparky.ee.yaml:53:            {{- if hasKey $env "password" }}
compositions/xdatabases.database.sparky.ee.yaml:54:            POSTGRES_PASSWORD: {{ $env.password | quote }}
```

and the generated `EnvironmentConfig` ships the key empty rather than seeded:

```yaml
apiVersion: apiextensions.crossplane.io/v1beta1
kind: EnvironmentConfig
metadata:
  name: default
data:
  password: ""
```

The value comes from the environment at reconcile time, the XR spec never carries it, and the
emitter guards the whole `stringData` block on the key being present. CF-474 (#380) and CF-476
(#383) are holding on this starter, and the `environment-keys` annotation tells an operator
exactly which key to fill. Nothing to file.

**Watch-for, answered.** Is the envelope findable without knowing the word? Partly — the RDS
card tags itself `Envelopes` in the chooser, which is discoverable by browsing but is the word
itself, not a plainer synonym; the Portable Database starter reaches the same outcome through a
plain `Secret` node and never needs the term. Does anything warn when a secret-shaped field is
typed in plain? On this path the question does not arise: the starter never offers a plaintext
password field to type into — the value is an environment key, and the inspector shows it as
such.

**One candidate investigated and discarded.** Generate first appeared to be a silent no-op —
`out/` empty, no `/api/` request, no error, the `Preview only · Click Generate to write to …`
banner unchanged. It is not a defect: Generate raises a native confirm,
