## 3. Missions

### M1 — First contact: an S3 bucket, from nothing (blank start)

**Reached Generate. Oracle met.** Time to Generate ≈ 22 min including driver
authoring.

- **Arrival.** The Examples chooser opens by itself over the whole canvas, six
  starter blueprints including "AWS S3 Secure Storage Bucket". For a first-time
  user this is help rather than interruption, but it does cover every other
  control until dismissed.
- **Provider search finds the word a user knows.** `s3` in the KINDS search
  returns 50 hits with plain `Bucket` first; `bucket` returns 46, also
  `Bucket`-first. The package name is not needed.
- **First drag is discoverable — and unnecessary.** A plain **click** on a kind
  card adds it to the canvas (nodes 1 → 2). The palette also says "Drag a kind
  onto the canvas". Both work.
- **Wiring.** Dragging the XRD `region` port onto the Bucket `region` port
  produced `region: {from: params.region}` in the live document. The inspector
  then showed `← params.region` and flagged `⚠ optional param into required
  field` — an honest warning the user did not have to ask for.
- **Validate** reads `validation check unavailable` and explains why:
  `crossplane CLI not found on PATH` plus an install tip naming Docker. This is
  CF-093 and the degradation is graceful, not silent.
- **Generate** writes after a native `confirm()` ("Generate will write manifests
  to disk in '<outDir>'. Proceed?"), then the status line reads
  `written · 4 files · 3 previews`.

Oracle check on the written artifacts:

```yaml
# out/compositions/xapps.platform.example.org.yaml
region: {{ $spec.region | quote }}
# out/xrds/xapps.platform.example.org.yaml
region:
  type: string
```

Both halves of the M1 oracle hold. Validate could not be run green (Docker
absent, CF-093), so the mission stops at Generate as the run prompt directs.

**Harness note, not a finding:** an earlier pass appeared to show Generate
silently writing nothing — `POST /api/generate {"write":false}` returning HTTP
200 with full paths and byte counts while the output directory stayed empty.
That was the scripted driver auto-dismissing the `confirm()` dialog. With the
dialog accepted, the UI issues a second `POST /api/generate {"write":true}` and
the files appear. The preview/confirm/write sequence is correct.

### M2 — The status wire: IRSA (blank start)

**Blocked before the oracle; no finding filed.** The mission needs an IAM Role,
and `provider-aws-iam` is not in the seeded cache (`tests/fixtures/cache` holds
only `provider-aws-s3` and `provider-aws-sqs`). Fetching it fails exactly where

That is #68 and is not filed.

What was still learned, with a native `ServiceAccount` on the canvas:

- Status sources are **visually typed** — status ports carry their own class and
  render in a separate `outputs` group on the card, distinct from spec fields,
  so a user can see that a status field is wireable without being told.
- The ServiceAccount inspector does expose an **ANNOTATIONS** section and a
  `+ Standard Labels` affordance, so the annotation target M2 asks about exists
  and is reachable from the inspector rather than hidden.
- The guard and layout halves of the M2 oracle could not be judged without the
  Role, so they are simply not reported.
