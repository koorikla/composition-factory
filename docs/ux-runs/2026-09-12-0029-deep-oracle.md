That is CF-183 (#68) and is not filed. Rather than stop, M2's actual subject —
**a status field driving an annotation on another resource** — was exercised with
an SQS `Queue` standing in for the IAM Role and a native `ServiceAccount`:

- **Status fields are visibly sources.** Status ports carry their own class and
  render in a separate `outputs` group on the card (`name / id`, `arn`), plainly
  distinct from spec fields.
- **The annotation is reachable and becomes a wire target.** The inspector's
  ANNOTATIONS section takes a `prefix/name` and a value. Adding
  `eks.amazonaws.com/role-arn` immediately created a port
  `[port] service-account :: annotations.eks.amazonaws.com/role-arn`.
- **The drag works.** Dragging `queue :: status.atProvider.arn` onto it produced:

  ```json
  "annotations": {
    "eks.amazonaws.com/role-arn": { "from": "resources.queue.status.atProvider.arn" }

  ```

- **The guard appears without being asked for** — the M2 watch item. Emitted:

  ```
  {{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
  'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "queue").resource.status.atProvider.arn | quote }}
  {{- end }}
  ```

  The key is correctly single-quoted, and the binding is guarded on the source
  actually having reported.
- **Layout puts the source first.** Auto-layout gives XApp `x=256`, Queue
  `x=514`, ServiceAccount `x=772` — the dependency reads left to right.

Every part of the M2 oracle that does not require the IAM Role itself holds.

## 5. Filed

| Id | Issue | Severity | Scale | Title |
|---|---|---|---|---|
| CF-344 | #232 | P0 | engine | Emitted XRD and EnvironmentConfig write `on`/`off`/`yes`/`no` keys unquoted, so Kubernetes reads them as booleans |
| CF-345 | #235 | P1 | ux | `cf serve` drops every cached provider kind on the first blueprint save, and a reload does not restore them |

**Why CF-344 is P0 rather than P1.** The first repro marked `on` as required, so
`required` decoded to `[true, "providerName"]` and the API server would at least
reject the XRD on a type error. Marking none of the four boolean-like names
required removes that last loud signal: `cf gen` exits 0, `required:
[providerName]` is well-formed, and the decode still collapses five declared
parameters into three —

```
declared in the blueprint: on, off, yes, no, providerName  (5 parameters)
what the API server sees:  ["false" "providerName" "true"]  (3 properties)
required:                  []interface {}{"providerName"}
```

`on` and `yes` merge into one property named `true`, `off` and `no` into one
named `false`, and whichever the emitter wrote second silently wins. Wrong
output, exit 0, no signal — the P0 row of `backlog-authoring` §3 exactly.

**Commented** on **#198 (CF-309)** and **#147 (CF-259)** linking CF-344 as
residue of the same family, per the residue rule (new id, comment on the old,
never reopen).

**Id collision, corrected.** #232 was filed at 00:51 UTC as CF-340, computed
against a max of CF-339 (#228); #229 took CF-340 at 00:48 UTC while that
computation was in flight. Ids are permanent, so #232 was renumbered to
**CF-344** and a comment on it records the change. CF-340 refers to #229 only.
The lesson for future runs: on a repository this actively filed, re-read the max
id immediately before `issue_write`, not at the start of the filing step.

## 6. Looked at and deliberately NOT filed

Recorded so the next run does not re-raise them.

- **Generate appeared to write nothing.** `POST /api/generate {"write":false}`
  returns HTTP 200 with full paths and byte counts while the output directory
  stays empty. That is the *preview* leg: the UI then raises a native
  `confirm()`, and on acceptance issues `POST /api/generate {"write":true}` and
  the files appear. The scripted driver was auto-dismissing the dialog.
  Harness artifact, not a defect.
- **Generate refusing on a missing required field is loud, not silent.** With
  `Queue.region` unset, the write leg returns `HTTP 400 {"error":"resource
  \"queue\": missing required field \"region\" in Queue spec.forProvider"}` and
  the canvas raises a `toast-error` carrying that exact sentence. Correct.
- **"KINDS search cannot find Queue".** A driver bug: Playwright `hasText`
  regexes were anchored with `\s` against unspaced `textContent`, so `/^Queue\s/`
  never matched. The search is fine (see Extra areas).
- **A 404 in the browser console on load.** Present throughout, but no
  `requestfailed` or `response >= 400` was captured for it and it never affected
  behaviour; not chased to a cause and too thin to file.
- **`{{- if or (hasKey $spec "region") }}`** — a single-argument `or` in emitted
  templates. Valid Go template, correct output; a style observation, which
  `backlog-authoring` §2 excludes explicitly.
