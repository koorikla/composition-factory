## 4. Mission M1 — first contact: an S3 bucket, from nothing

**Outcome: completed.** Blank start. Time to generated artifacts: ~8 minutes of driver
steps. Validate not reachable (Docker absent, CF-093), so the run stops at Generate and
uses the emitted YAML as the oracle, as instructed.

### Narrative

On arrival the canvas is covered by a full-screen modal, `#examplesOverlay`
("STARTER BLUEPRINTS — Choose an Example Blueprint"), 1600×1000, `z-index: 100`. It
takes the whole viewport before you have done anything. `Escape` dismisses it, and so
does its `×`. For a mission that begins "you have never used this tool" this is a
reasonable thing to meet first — it names what the tool makes — but it *is* a wall
between arrival and the canvas.

Typing `s3` into **Search kinds…** worked on the word a user knows. Dragging `Bucket`
from the palette onto the canvas worked first time, and the drag did something better
than I expected: it **added the provider as a blueprint source by itself**, so
`spec.sources` gained `ghcr.io/crossplane-contrib/provider-aws-s3:v2.7.0` without my
asking. No separate "install the provider" step.

`+ Add parameter` creates `newParam` (string, optional) and puts the name in an inline
editable field; typing `region` + Enter renamed it. Wiring was a plain drag from the
`region` parameter port on the XRD card to the `region` port on the Bucket card — one
attempt, and the Bucket's `region` row immediately grew a `⚠` badge
(`port req port-opt-warn`), which is the tool telling me I had wired a *required*
provider field to an *optional* XR parameter. That warning is the right call and it
arrived without being asked for.

Generate opens a `confirm()` — *"Generate will write manifests to disk in '…'. Proceed?"* —
and writes four files.

### Oracle

Met. The emitted Composition carries the Bucket with its region from the XR parameter,
hasKey-guarded:

```yaml
apiVersion: s3.aws.m.upbound.io/v1beta1
kind: Bucket
spec:
  forProvider:
    {{- if or (hasKey $spec "region") }}
    {{- if hasKey $spec "region" }}
    region: {{ $spec.region | quote }}
    {{- end }}
    {{- else }}
    {}
    {{- end }}
```

and the XRD declares it with its type:

```yaml
region:
  type: string
required: [providerName]
```

### Round-trip

Clean, and better than clean. `cf adopt` on the emitted Composition alone reports its
losses out loud rather than swallowing them:

```
Adopt loss report (2 dropped item(s)):
  - pipeline.auto-ready: without functions.yaml, function package could not be recovered …
  - xrd.parameters.region: without the XRD, default, enum and description could not be
    recovered (combine XRD and Composition into one file, or import XRD to complement)
```

Regenerating from the adopted blueprint produces a Composition **byte-identical** to the
original (`diff` → no output). Following the loss report's own advice — concatenating the
XRD and the Composition with a `---` separator — makes adopt report **zero** losses and
recover the exact `description`. The remediation the tool suggests actually works.

- Loading the RDS starter → `400 POST /api/examples/rds-postgres/load`, UI shows

  and — importantly — **the blueprint on disk is left untouched**: `resources: []`,

I twice thought I had a P0 here and twice I was wrong, which is worth recording:

1. **"Generate does nothing."** Two presses, zero network requests, empty `out/`. The

   cancelling the `confirm()`. With a dialog handler attached, Generate works. **Driver
   artifact, not filed.**
2. **"Provider add fails silently."** My first scan for error text found nothing at
   t+1s…t+20s. A second pass with unfiltered full-text snapshots found the error at
   **t+0.8s**, persisting. My filter was wrong, not the UI. **Not filed.**

The substitute target (SQS, cached) loaded fine: `200 POST /api/examples/sqs-queue/load`,

### CF-459 — canvas serves no favicon; every load logs a console 404

The served canvas HTML declares no `<link rel="icon">`, so every browser fetches
`/favicon.ico`, which the engine 404s:

```
$ curl -s http://127.0.0.1:19310/ | grep -iE 'rel=.?(icon|shortcut)'
NO <link rel=icon> in the served HTML

$ curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:19310/favicon.ico
404        # attempt 1
404        # attempt 2

$ curl -s http://127.0.0.1:19310/favicon.ico
404 page not found
```

Observed in the browser on **every one of ~12 page loads** across this run:

```
CONSOLE.error: Failed to load resource: the server responded with a status of 404 (Not Found)
```

Cost: `canvas-ux-tester` SKILL.md §3 makes "call `read_console_messages` after every
mission phase" the rule, and an uncaught page error an automatic P0. A permanent,
expected console error on every load is exactly the noise that trains a reader to stop
looking at that channel — I had to filter it out by hand in every driver in this run to
see anything else. Contract: a page load of the canvas must leave the console clean.
