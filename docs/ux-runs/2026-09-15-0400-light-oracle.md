## 3. Mission M1 — first contact: an S3 bucket, from nothing

Blank blueprint, seeded cache, `cf serve --addr 127.0.0.1:19320`. Run to Generate
(Validate reads unavailable here — Docker absent, CF-093).

**Oracle: met.** The generated Composition carries an S3 `Bucket` whose `region` comes
from the XR parameter, and the XRD declares the parameter with its type:

```json
"params after wire": {
  "providerName": {"type":"string","required":true,"description":"ProviderConfig to reconcile the composed resources against."},
  "region": {"type":"string","required":false}
}
"bucket fields": [{"region":{"from":"params.region"}}]
```

Generate wrote 4 files; the Composition's template guards the field as expected
(`{{- if or (hasKey $spec "region") }}`).

### What the canvas puts in front of you on arrival

### The first drag, and the Inspector

KINDS → `Bucket` gives 23 rows under a `S3.AWS.M.UPBOUND.IO` group header captioned
`NAMESPACED (V2) · MATCHES XRD`, each `draggable="true"` and annotated `1 req`. Dragging
the first onto the canvas worked on the first attempt and produced `Bucket/bucket`.

The Inspector then does the mission's hardest step without being asked: an **ESSENTIALS**
panel with a `REGION string` row and a `Val | Wire | Raw` toggle. `Wire` opens a select
offering `wire to…`, `params.providerName`, `+ new XRD parameter…`; choosing the last
gives a `parameterName` input, and typing `region` + Enter created the parameter and bound
the field in one step. This is the path M1 exists to test and it is discoverable.

One thing worth noting rather than filing: `region` arrives pre-filled with the literal
`us-east-1` under `Val`, and the parameter the wire flow creates is `required: false` —
so the default M1 path lands exactly in the CF-493 condition (optional parameter feeding a
required field). It is now warned about at both the CLI and the API, which is the fix
working as intended on the most likely first-run blueprint.
