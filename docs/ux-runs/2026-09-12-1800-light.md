### CF-432 (#324) and CF-461 (#357) — zero-preserving env defaults, round-tripped — fixed

Verified together as one `gen → adopt` round trip on a blueprint declaring `boolean` and
`integer` environment keys with defaults, against the seeded SQS cache. The emitter now uses the
zero-preserving `ternary`/`hasKey` form, so an explicit `false` or `0` in an `EnvironmentConfig`
survives:

```
delaySeconds: {{ ternary (index $env "delaySeconds") 30 (hasKey $env "delaySeconds") }}
{{- if ternary (index $env "enabled") true (hasKey $env "enabled") }}
{{- range $i := until (int (ternary (index $env "retries") 3 (hasKey $env "retries"))) }}
```

and `cf adopt` reads all three forms back — the `when` guard, the `forEach` loop and the field
wire all return as canonical `env.<key>` references:

```
      delaySeconds:
        from: env.delaySeconds
    forEach: env.retries
    when: env.enabled
```

Both runs identical. **Filed on the side of this check: CF-466 (#363)** — the same round trip
loses the *declared type* of an environment key used only as a field wire (`integer` → `string`),
and the re-generate then refuses. Confirmed independent of these two fixes: the same downgrade
occurs with the pre-CF-432 Sprig `default` form substituted into the Composition, so it is a
pre-existing defect, not residue. See §4.

## 3. Mission M3 — connection secret

**Blocked at its literal subject, completed in substance with a substitute kind.**

M3 asks for an RDS PostgreSQL instance whose credentials reach the app as a connection Secret.
No RDS or Postgres schema is reachable here: the seeded cache (`tests/fixtures/cache`) carries
only `provider-aws-s3` and `provider-aws-sqs`, and the ghcr.io blob CDN is denied, so
`cf provider add` cannot fetch one. Searching the kind palette by the words a user would know
returns nothing:

```
search "postgres" -> 0 hits: []
search "rds"      -> 0 hits: []
search "database" -> 0 hits: []
search "secret"   -> 1 hits: ["Secret"]
```

This is the known schema wall (#68, and #355 for the rds-postgres starter specifically) and is
**not filed**. The mission continued on an SQS `Queue`, which carries the same connection-secret
envelope, to test the parts of M3 that do not depend on the kind.

**What the canvas puts in front of you on arrival.** A modal, `STARTER BLUEPRINTS — Choose an
Example Blueprint`, opens over the canvas before the user has done anything, on a blank
document. Behind it the empty canvas carries its own instructions
(`1. DRAG KINDS FROM KINDS  2. ADD CLOUD PROVIDERS IN SOURCES`, noting 16 native kinds are ready
without providers). The modal closes cleanly on `×`. Recorded as an observation, not filed: a
first-run example chooser is a defensible design choice, and judging it either way is a product
call rather than a defect.

**Is the envelope findable without knowing the word "envelope"?** Yes. Selecting the Queue and
reading the Inspector top to bottom reaches a titled section with a plain-language subtitle:

```
CROSSPLANE ENVELOPE
Secrets, policies and metadata outside forProvider:
...
writeConnectionSecretToRef.name   string   REQ   Val | Wire | Raw
Name of the secret.
```

A user looking for where the connection secret goes does not have to know the term to find it —
"Secrets, policies and metadata outside forProvider" is the sentence that gets them there.

**Does a typed secret name reach the output?** Yes. Typing `app-postgres-conn` into that field
with real keystrokes reaches the emitted Composition intact:

```yaml
          spec:
            forProvider:
              region: 'us-east-1'
            providerConfigRef:
              kind: ClusterProviderConfig
              name: {{ $spec.providerName }}
            writeConnectionSecretToRef:
              name: 'app-postgres-conn'
```

**Generate** reached and reported `preview · 4 files · 3 previews`. `POST /api/generate` with an
empty body returns the rendered artifacts as a preview without writing them to `--out`; the
files appear only on an explicit write. That is a deliberate preview-then-write design, not a
defect.

**Validate** reads `validation check unavailable` — CF-093, Docker absent. Expected, not filed.

No console errors and no page errors were raised at any point in the mission.

**Watch item not reachable:** "whether anything warns you when a secret-shaped field is typed in
