4. **Manifest Editing & Credential Validation**:
   - Evaluated credential requirements:
     - The RDS schema defines `passwordSecretRef` (optional reference) and `autoGeneratePassword` (boolean).
     - When `autoGeneratePassword: true` is set, Crossplane automatically generates a cryptographically strong master password and stores it in the secret referenced by `writeConnectionSecretToRef`, avoiding literal passwords or manual secret scaffolding.


   - Inspected the **Crossplane Envelope** section at the bottom of the inspector:
     - `managementPolicies`: optional array.
     - `providerConfigRef.name`: marked `AUTO` (derived from `$spec.providerName`).
     - `providerConfigRef.kind`: marked `AUTO`.
     - `writeConnectionSecretToRef.name`: marked `REQ` (required in Upbound RDS Instance).
   - Clicked `Wire` (`w`) on `writeConnectionSecretToRef.name`.
   - In dropdown (`select[data-env-wire]`), chose `+ new XRD parameter…`.
   - Inline parameter creator expanded: entered `dbSecretName`, type `string`, checked `req`, and clicked `Add` (`button[data-npok]`).
   - Blueprint successfully updated:
     - XRD added `dbSecretName` under `spec.xrd.parameters`.
     - Envelope configured: `envelope: { "writeConnectionSecretToRef.name": { "from": "params.dbSecretName" } }`.
   - *Surfaced Defect*: Upon clicking `Add`, the inline new parameter inputs lingered in the inspector row due to missing `state.render()` in the resolution callback (filed as **CF-475**).

  - **Severity**: `severity:P2`
  - **Scale**: `scale:ux`
  - **Status**: `verified`
  - **Mechanism**: In `web-proto/js/regions/inspector/events.js:275-277`, the `[data-npok]` handler runs `setField` / `setEnvelopeField`, triggering a store `"doc"` event while `state.pendingNewParam` is still non-null.
