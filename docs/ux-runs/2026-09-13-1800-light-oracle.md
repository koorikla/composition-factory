## 3. Mission M3 — connection secret, Postgres credentials

Blank start, engine on `127.0.0.1:19320`, blank blueprint path
`/tmp/claude-0/ux/m3/rds.cf.yaml`, seeded cache copied to `--cache-dir`. Stopped at Generate
(Docker absent, so Validate is unavailable — CF-093).

**Arrival.** The canvas opens with the starter-blueprint chooser already in front of
everything, eleven cards deep, over a board that has already scaffolded an `XApp` with a
`providerName` parameter. A user who came to make a Postgres instance reads the card titles,
and one of them — "AWS RDS PostgreSQL Database … credentials connection secret envelope" —
is the mission, so the chooser earns its place here.

**Where the mission stopped.** Loading that card fails in this environment, and says so
plainly, both in the card and in a toast:

```
failed to cache provider: unable to fetch source "ghcr.io/crossplane-contrib/provider-aws-rds:v2.7.0":
ghcr.io/crossplane-contrib/provider-aws-rds:v2.7.0: read image config: Get
"https://pkg-containers.githubusercontent.com/ghcrblobs11/blobs/sha256:604c586c3afb…": Forbidden
```

That is the denied CDN (#68), not a finding — and the failure is reported well: the message
names the package, the operation and the cause, and the card stays where it was rather than
half-loading. No console errors.

**The native path.** The nearest reachable version of the same question is the Portable
Database starter (StatefulSet + Service + credentials Secret, no provider fetch). It loads in
one click, lays out four nodes, and the credential question answers itself in the Inspector:
`stringData[POSTGRES_PASSWORD]` is on the Secret card, sourced from the environment rather
than from the XR spec, which is CF-476's fix seen from the user's side. The word "envelope"
is never needed to get there.

**Outcome.** Mission partially completed: the RDS leg is blocked by egress; the credential
leg reached Generate on the native equivalent and the emitted Composition carries no literal
password.
