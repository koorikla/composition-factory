## 3. Mission — M2, the status wire

**Goal.** An IAM Role plus a ServiceAccount annotated with that Role's ARN, where the annotation
cannot be written until the Role reports it.

**Where the missing schemas stopped me.** The seeded cache checked in by CF-183 (#68) holds
`provider-aws-s3` and `provider-aws-sqs` only — no IAM, no cloud Kubernetes provider. Adding the
IAM provider from the catalogue fails on the blocked ghcr blob CDN, and the canvas says so
plainly (reproduced twice, `POST /api/providers` → 502):

```
Failed to fetch package from registry: could not fetch package:
ghcr.io/crossplane-contrib/provider-aws-iam:v2.7.0: read image config: Get
"https://pkg-containers.githubusercontent.com/ghcrblobs20/blobs/sha256:a7f6220c7fdd…": Forbidden.
```

That is the documented environment limit, not a defect — and the failure is reported loudly, with
the ref and the cause, which is the behaviour the mission wants.

**Substitution.** To exercise the mission's actual mechanism I swapped the source: an SQS `Queue`
(status `atProvider.arn`, in the seeded cache) into a native `ServiceAccount`'s
`eks.amazonaws.com/role-arn` annotation. Same shape as IRSA — a status field that does not exist
until the provider reports it, bound to an annotation on a native object.

**Outcome — the mission's oracle is met on the substituted source.**

1. *How you learn a status field can be a source*: the Queue card itself carries an `outputs`
   section listing `name / id`, `arn`, `contentBasedDeduplication`, `deduplicationScope`,
   `delaySeconds`, `fifoQueue`, each with an output dot. Nothing to discover — it is on the card.
2. *Whether dragging onto an annotation is discoverable*: yes. Adding the annotation puts an
   `annotations` section with its own input dot on the ServiceAccount card, so the annotation is a
   drop target exactly like a spec field.
3. *Whether the guard appears without asking*: yes, unprompted:

```gotemplate
{{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "queue").resource.status.atProvider.arn | quote }}
{{- end }}
```

4. *Whether the canvas lays the dependency*: yes — the ServiceAccount card moved to the right of
   the Queue on wiring, so the source precedes the consumer.
5. *Whether the wire is readable once drawn*: on the canvas yes, a green curve from `arn` to the
   annotation row. In the inspector no — CF-139 (#24), above.

**Generate.** Confirms before writing, then writes:

```
Generate will write manifests to disk in '…/m2/out', overwriting existing files.

Proceed?
```

→ `written · 4 files · 3 previews`, banner `✓ Output written to …/m2/out · Apply: kubectl apply -R -f …`,
and on disk: `compositions/xapps.platform.example.org.yaml`, `xrds/xapps.platform.example.org.yaml`,
`functions.yaml`, `providerconfigs/aws.yaml`.

Validate not exercised: Docker is absent in this environment (CF-093, #8).
