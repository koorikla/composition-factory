## 3. Mission M2 — the status wire

**Blank start**, `doc.cf.yaml` absent, engine on 19320 with the seeded cache from

### 3.1 First contact

The canvas does not open on the canvas. A modal, **"Choose an Example Blueprint"**, covers it
before the user has done anything, offering seven starter blueprints. For M2 this happens to be a
gift — one card is literally *AWS IRSA (IAM Role + EKS ServiceAccount)*, tagged `Status Wire` and
`Annotations`, which is the mission stated back to the user. The card is honest about its cost
up front: `↓ 1 provider`, `3 resources`.

### 3.2 Where the missing schema stops the mission

Loading the IRSA card needs `provider-aws-iam`, which is not in the seeded cache and cannot be
fetched here (the ghcr.io blob CDN is denied). The mission stops there, as expected — recorded,
not filed (CF-183, #68).

The failure itself is handled **correctly**, and this is worth recording as a positive: the tool
reports it in two places and changes nothing.

```
failed to cache provider: unable to fetch source "ghcr.io/crossplane-contrib/provider-aws-iam:v2.7.0":
ghcr.io/crossplane-contrib/provider-aws-iam:v2.7.0: read image config: Get
"https://pkg-containers.githubusercontent.com/ghcrblobs20/blobs/sha256:a7f6220c...": Forbidden
```

The message appears as a toast and inline on the IRSA card; the modal stays open and the blank
blueprint is **not** replaced. No silent partial load, no half-populated canvas — the two outcomes
that would have been P0 under the Round-Trip Rule.

Observation, not filed: the user-facing string is the raw registry error, including a ~400-character
signed blob URL whose query parameters are all `REDACTED`. A first-time user learns "something
called pkg-containers said Forbidden" rather than "the provider could not be downloaded". This is
only reachable by denying egress, which is this container's condition and the subject of #68, so it
is not filed as a separate finding — but if a driver touches provider-fetch error text, it is worth
folding in.

### 3.3 The mission's contract, verified on the cache-backed path

To reach the M2 oracle without the IAM schema, the same shape — a status field as a source, bound
into a dependent resource, guarded — was exercised through the SQS starter blueprint, which is
`ready` from the cache. Loaded, then **Generate**.

Generate prompted before writing (`Generate will write manifests to disk in '.../out'. Proceed?`)
and wrote 4 files. The status wire in the generated Composition:

```yaml
{{- if hasKey (dig "resources" "main-queue" "resource" "status" "atProvider" dict $.observed) "url" }}
queueUrl: {{ (index $.observed.resources "main-queue").resource.status.atProvider.url | quote }}
```

Against the M2 oracle: the binding is to a status field on another resource, **the guard is present
and appeared without being asked for**, `dig ... dict` gives it a safe default so an absent status
during early reconciliation cannot hard-fail under `options: ["missingkey=error"]`, and the wire
reads legibly in the preview pane. The canvas also surfaced an unprompted warning about a
neighbouring field — `1 field uses a raw template (queue-policy.policy) — raw values bypass CRD
schema validation; missingkey=error still guards it` — which is the tool volunteering the right
information at the right moment.

Validate was not exercised: Docker is absent, so it reads "unavailable" (CF-093).

**Mission result: reached Generate, oracle satisfied on the cache-backed path; the IRSA path itself
