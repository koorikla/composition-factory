## 4. Issues Filed

One issue filed, within the cap of six.

| id | issue | severity | scale |
|---|---|---|---|
| CF-472 | [#370](https://github.com/koorikla/composition-factory/issues/370) — Startup indexing of pre-cached providers violates CF-465 deferral and leaks test state across runs | P2 | engine |

### Root Cause & Defect Analysis
In commit `658987d` (CF-463), `cmd/cf/options.go:AssembleProviders` was updated to iterate over `store.List()` and append all cached providers to `srv.Providers` at server startup:
```go
cached, _ := store.List()
for _, p := range cached {
    if !seen[p] {
        seen[p] = true
        refs = append(refs, p)
    }
}
```

This violates the deferred loading contract introduced in CF-465, which specifies that unreferenced providers in the cache (like S3) must not be loaded into memory or exposed via `/api/providers` until explicitly referenced in blueprint sources or added by the user.

Test 3 of `tests/cf465-palette-background-providers.spec.js` explicitly tests this invariant:
```javascript
const res = await page.request.get('http://127.0.0.1:26438/api/providers');
const data = await res.json();
const s3 = (data.providers || []).find(p => p.ref.includes('provider-aws-s3'));
expect(s3).toBeUndefined();
```

When `cf465` runs in isolation, Test 3 fails. In full-suite and CI runs, the failure was masked because `tests/cf126-remove-provider-discoverability.spec.js` ran earlier in alphabetical order and issued `DELETE /api/providers/ghcr.io/crossplane-contrib/provider-aws-s3:v2.7.0`, clearing S3 from memory before `cf465` executed.
