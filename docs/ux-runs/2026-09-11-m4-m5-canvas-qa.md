## 2. Narrative

### Phase 1: M4 Adoption & Round-Trip
The canvas initialized on port 8090 with a blank document. The empty state displayed the XRD card and the prompt to add resources or import an existing manifest.

Using the hidden `#importFile` file input triggered by the `#importBtn` interface control, we uploaded `testdata/xqueue-pipeline.composition.golden.yaml`. The application presented a confirmation dialog stating:
> *"Import will replace doc.cf.yaml (undoable). Proceed?"*

Upon confirming:
- The canvas smoothly animated and rendered two cards: `xrd` (`XQueue`) and `main-queue` (`Queue`, `sqs.aws.m.upbound.io/v1beta1`).
- The dependency wire connecting `params.providerName` to `main-queue.spec.providerConfigRef.name` appeared as an SVG spline.
- A yellow warning toast appeared:
  > *"adopted with 1 dropped item: xrd.parameters.maxMessageSize (without the XRD, default, enum and description could not be recovered (combine XRD and Composition into one file, or import XRD to complement))"*
  This clearly communicated why scalar metadata was not recovered without an XRD document.
- Card dragging functioned properly; dragging `xrd` moved the card smoothly, and wire recalculation kept the SVG spline attached to the port coordinates.
- Clicking cards opened the right-hand inspector panel. The `main-queue` inspector displayed 18 leaf fields, loop/when controls, and wire bindings.
- Clicking the "Generate" button opened a confirmation modal:
  > *"Generate will write manifests to disk in '.testrun-ux/out', overwriting existing files. Proceed?"*
  Manifest generation completed successfully. Comparing the generated output `.testrun-ux/out/compositions/xqueues.platform.sparky.ee.yaml` against the source golden manifest produced a bit-for-bit identical file with zero diff.

Selecting different nodes properly refreshed the inspector panel without triggering any uncaught JavaScript exceptions.

### Phase 3: Engine Selector Investigation
On the `Cloud-Agnostic Web Workload` (which uses pure native Kubernetes resources without Go templates or conventions), changing `#engineSel` to `kcl` and `python` succeeded:
- `doc.spec.emit.engine` was persisted to the server.
- The inspector and generator adjusted to the respective engine without error.

However, when testing engine switching on `AWS IRSA` or the pristine `xnotify` blueprint (which contain `spec.conventions` or Go template strings):
- The server rejected `PUT /api/blueprint` with `HTTP 400 Bad Request: spec.conventions: engine "kcl" does not support template: conventions`.
- The user expected to see an error toast explaining why KCL could not be selected, and expected the select box to stay at or revert to `go-templating`.
- Instead, the UI showed `#engineSel` displaying `kcl`!
- No error toast was visible.
- Checking the server state revealed that the blueprint on disk was still `go-templating`, and generating files wrote Go templating manifests.
- Tracing the root cause revealed that `output.js:1176` called `.then(() => store.generate(false))` unconditionally. Because `replaceDoc` returns `null` on failure (rather than rejecting), `store.generate(false)` ran against the previous unmutated document, succeeded, and fired `"generate"`, which in turn invoked `clearErrorToast()` in `main.js:103`, obliterating the error toast before it could be perceived.

### Phase 4: Wires, Parameters & Keyboard Shortcuts
Testing on `AWS SQS Queue with Dead Letter Queue`:
- **Wire selection:** Clicking an SVG wire path (`svg.wires path.wire-path`) selected the wire and displayed the `.wire-del-btn` hover handle.
- **Escape key:** Pressing `Escape` deselected the wire and cleared active inspector highlights.
- **Delete / Backspace:** Pressing `Delete` while a wire was selected deleted the wire, reducing wire count from 6 to 5 (confirming CF-220 fix).
- **Undo / Redo:** Pressing `Meta+Z` restored the deleted wire (wire count back to 6); pressing `Meta+Shift+Z` re-deleted it (wire count 5).
- **Inspector unwire button:** Clicking the `×` button on a wired field (`[data-unwire]`) unwired the connection cleanly and supported full undo/redo.
- **Wiring field via dropdown:** Clicking `[data-m="w"]` (Wire mode) on a field revealed `select[data-wire]`, listing type-compatible parameters and upstream status fields. Selecting a target created a wire immediately.
- **Deleting wired parameters:** Deleting a parameter wired to 3 resources (`region`) prompted a confirmation dialog:
  > *"Parameter 'region' is wired into 3 fields. Delete it and unwire all referencing fields?"*
  Confirming deleted the parameter and unwired all referencing fields without error.

## 3. Findings

### P1 — CF-225: Changing engine to an unsupported choice silently clears error toast and desynchronizes selector
- **Severity:** P1
- **Scale:** `scale:ux`
- **Status:** Verified (reproduced twice against clean state; issue filed: [#112](https://github.com/koorikla/composition-factory/issues/112))
- **Spec:** `tests/slice93-engine-selector-desync.spec.js` (fails with locator `#canvas-error-toast` not found)
- **Mechanism:**
  In `web-proto/js/regions/output.js:1162-1178`:
  ```javascript
  if (el.engineSel) {
    el.engineSel.addEventListener("change", function () {
      var val = el.engineSel.value;
      store.replaceDoc(function (doc) {
        ...
      }).then(function () { store.generate(false); });
    });
  }
  ```
  When `PUT /api/blueprint` fails validation (e.g. 400 for `engine "kcl" does not support template: conventions`), `store._replaceDocNow` emits `"error"` and resolves with `null`. `main.js:88` creates `#canvas-error-toast`. Then the `.then` callback immediately runs `store.generate(false)` with the unchanged valid document, which succeeds and emits `"generate"`. `main.js:103` clears the toast on `"generate"`. Because `doc` was not emitted, `drawTopbar` never runs, leaving `#engineSel` displaying `kcl` while the document remains `go-templating`.
