## 4. Missions

### M1 — First contact: an S3 bucket, from nothing · **completed**

Time to Generate: not separately instrumented. The whole run — gates,
verification, both missions, the extra area and the write-up — took 19 minutes
wall-clock (21:29:45 → 21:48:46 UTC) against a 2.5 h cap, of which M1 was a
handful of minutes including the false-positive detour below. A scripted driver
cannot report hesitation, so these numbers measure the machine, not a user.
Validate is unavailable (CF-093), so per the run parameters the generated YAML is
the oracle.

**Narrative.** Arrival puts the "Choose an Example Blueprint" modal in front of
everything before you have touched anything. For M1's naive user that is an
interruption — you arrive wanting to build, and the first interaction is
dismissing a wall of nine cards — but it is also the single clearest statement of
what this tool is for, and the onboarding card underneath ("1. DRAG KINDS FROM
KINDS  2. ADD CLOUD PROVIDERS IN SOURCES") is now fully legible and clear of the
Inspector rail, so **CF-486 reads as fixed from the user's side**.

Typing `s3` into the kinds search found the provider by the word a user knows,
not the package name — `S3.AWS.M.UPBOUND.IO`, 25 kinds, no ceremony. That is the
thing M1 is watching for and it works. What does not work is reading the result;
see finding 2.

The first drag onto the canvas landed on the first attempt. Selecting the Bucket
gives an ESSENTIALS block with `REGION` and a `Val / Wire / Raw` switch —
switching to `Wire` offered `params.providerName` and `+ new XRD parameter…`, and
choosing the latter opened an inline form that took the name `region` and
**closed on submission** (CF-475's behaviour holds). The wire drew immediately
and the manifest preview changed to `region: {from: params.region}` in the same
tick.

**Oracle — met.** Generated Composition:

```yaml
apiVersion: s3.aws.m.upbound.io/v1beta1
kind: Bucket
spec:
  forProvider:
    {{- if or (hasKey $spec "region") }}
    {{- if hasKey $spec "region" }}
    region: {{ $spec.region | quote }}
    {{- end }}
    {{- else }}
    {}
    {{- end }}
```

and the XRD declares it with its type:

```yaml
region:
  type: string
```

*Observation, not filed:* the emitted guard is `if or (hasKey …)` — a single-
argument `or` — wrapping a second, identical `hasKey` on the same key. It is
correct and it renders, but it is two redundant layers in the artifact the user
ships and reviews. Recorded here rather than filed: it is emitted-output tidiness,
not a moment where the tool did the wrong thing.

**A false positive I talked myself into, recorded so the next run does not repeat
it.** Clicking Generate appeared to do nothing: no network request, no file, no
message, button visible and enabled, and the page itself confirmed it received
the click on `#generateBtn`. I had it written up as a P0 before checking the
handler — `generateNow()` calls `window.confirm()`, and headless Playwright
auto-dismisses dialogs, so *my driver* was answering "no" every time. With a
dialog handler attached, Generate writes all four files and the header flips to
`written · 4 files · 3 previews`. **Not a defect.** The lesson for scripted
drivers in this repo: attach `page.on('dialog', …)` before judging any
write-path button inert.

### M2 — The status wire: IRSA · **completed, with a substitution**

**The mission's own subject could not be run as written.** M2 wants an IAM Role;
the seeded cache carries only `provider-aws-s3` and `provider-aws-sqs`, and
searching `iam` returns zero kinds. Adding `provider-aws-iam` needs the ghcr.io
blob CDN, which this environment denies — that is CF-183 (#68) and is not filed.
I substituted the SQS `Queue` as the status-reporting resource, which exercises
exactly what M2 is built to measure: whether a status field can be discovered as
a wire source, whether an annotation can be the target, whether the guard appears
unasked, and whether the dependency is laid out in order.

**Narrative.** The zero-result state for `iam` is genuinely good: "No kinds match
search query. Add a provider in SOURCES.", followed by a `MATCHING CATALOGUE
PROVIDERS` list with `provider-aws-iam` and an `Add` button right there. The tool
knows what I want and offers it. It is also where finding 1 lives — the captions
that explain *why* each row matched are cut off before the reason.

Dropping `Queue` and `ServiceAccount` worked first try each. The annotation flow
cost two rejected attempts before it took, and both rejections were the tool
being right: `Annotation key is required (e.g. prefix/name)`, then `Annotation
"eks.amazonaws.com/role-arn" requires a value (or a temporary placeholder to wire
later)`. That second message is doing real teaching — it names the exact
workaround for M2's central problem (the value cannot exist yet) in the sentence
where you hit it. You still have to type a throwaway `TBD` and then switch the
row to `Wire`, which is a two-step dance for a one-step intention, but it is
signposted rather than hidden, and CF-478's wire control on annotations is
present and works.

Once wired, the Inspector states the binding in one readable line:

```
queue.status.atProvider.arn → service-account.annotations.eks.amazonaws.com/role-arn
```

**Oracle — met.** The annotation is bound to the status field, the binding is
guarded, and the layout put the producer before the consumer
(`queue x=723`, `service-account x=964`):

```yaml
{{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: {{ $xr }}-service-account
  annotations:
    {{ setResourceNameAnnotation "service-account" }}
    {{- if hasKey (dig "resources" "queue" "resource" "status" "atProvider" dict $.observed) "arn" }}
    'eks.amazonaws.com/role-arn': {{ (index $.observed.resources "queue").resource.status.atProvider.arn | quote }}
    {{- end }}
{{- end }}
```

Note the **outer** guard around the whole resource, not just the annotation:
that is CF-482's fix visible from the user's side — the first pass does not emit
a ServiceAccount with the annotation missing.
