## Symptom

When running `cf gen -o <dir>` targeting an existing folder (such as a GitOps repository folder holding `kustomization.yaml`, `README.md`, or custom Kubernetes manifests), `cf gen` recursively deletes all files in `<dir>` that were not generated by the current execution. There is no warning, no `--prune` or `--force` flag, and no documentation of this destructive behavior.

When `-o .` is used (default), `cf gen` only cleans up files within its known managed directories (`compositions/`, `xrds/`, `providerconfigs/`, `runtime/`, `templates/`, and top-level `functions.yaml`, `rbac.yaml`). But when `-o <dir>` is specified, `findExistingManagedFiles` erroneously walked the entire tree of `<dir>` regardless of directory structure or file provenance.

## Evidence

Running `cf gen -o gitops`:
```sh
$ mkdir gitops
$ touch gitops/kustomization.yaml gitops/README.md
$ ./bin/cf gen internal/examples/sqs-queue.cf.yaml -o gitops
wrote gitops/compositions/xqueues.platform.sparky.ee.yaml
wrote gitops/functions.yaml
wrote gitops/providerconfigs/aws.yaml
wrote gitops/xrds/xqueues.platform.sparky.ee.yaml
removed gitops/README.md
removed gitops/kustomization.yaml
```
Both user files were deleted without warning or opt-in.

## Location

- `cmd/cf/gen.go:248-258`: `findExistingManagedFiles` branches on `cleanOut == "."`. In the `else` branch (when `-o` is not `.`), it walks all files in `cleanOut` indiscriminately.
- `cmd/cf/gen_test.go:394`: `TestGenCleansUpOrphanedFiles` places `orphaned.yaml` directly in `out` root rather than in a managed subdirectory (`compositions/`).

## Acceptance test

Write this test **first**, verbatim in `cmd/cf/gen_test.go`:

```go
func TestGenPreservesUnmanagedFilesInOutputDir(t *testing.T) {
	dir, bp, cacheDir := seed(t)
	out := filepath.Join(dir, "gitops")
	if err := os.MkdirAll(out, 0o755); err != nil {
		t.Fatal(err)
	}

	keepFiles := []string{
		filepath.Join(out, "kustomization.yaml"),
		filepath.Join(out, "README.md"),
		filepath.Join(out, "custom", "app.yaml"),
	}
	for _, f := range keepFiles {
		if err := os.MkdirAll(filepath.Dir(f), 0o755); err != nil {
			t.Fatal(err)
		}
		if err := os.WriteFile(f, []byte("# hand written\n"), 0o644); err != nil {
			t.Fatal(err)
		}
	}

	var buf bytes.Buffer
	cmd := &GenCmd{Blueprint: bp, Out: out, CacheDir: cacheDir}
	if err := cmd.Run(&buf); err != nil {
		t.Fatalf("Run: %v", err)
	}

	for _, f := range keepFiles {
		if _, err := os.Stat(f); err != nil {
			t.Errorf("hand-written file was deleted by cf gen: %s", f)
		}
	}
}
```

## Contract

- `findExistingManagedFiles` must restrict candidate files to the exact same managed scopes whether `-o` is `.` or another directory:
  - Subdirectories: `filepath.Join(out, d)` for `d` in `{"compositions", "xrds", "providerconfigs", "runtime", "templates"}`
  - Top files: `filepath.Join(out, f)` for `f` in `{"functions.yaml", "rbac.yaml"}`
- Files outside those managed paths (e.g. `kustomization.yaml`, `README.md`, arbitrary subdirectories) must never be walked or removed.
- Stale generated files in managed subdirectories (e.g. an old composition after an XRD rename) continue to be pruned cleanly.
- `docs/cli.md` accurately documents the cleanup behavior.
