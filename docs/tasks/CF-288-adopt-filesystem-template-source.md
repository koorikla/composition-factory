# CF-288 — adopt silently drops resources from Compositions using FileSystem templateSource without loss report

## Summary
When adopting a Composition that uses `function-go-templating` with `source: FileSystem` (as generated by `cf gen --template-source=FileSystem` or created by teams storing templates in external files), `Adopt` in `internal/adopt/adopt.go` silently ignores all resources without parsing them and without recording any loss in `bp.LossReport`.

The adoption succeeds with exit code 0, reporting no warnings or losses, but the resulting blueprint has 0 resources.

## Affected Locations
- `internal/adopt/adopt.go:1390-1399`

```go
if tmpl, ok := getNestedString(input, "inline", "template"); ok {
	resources, err := parseGoTemplateBody(tmpl)
	if err != nil {
		return nil, fmt.Errorf("parsing go-template body: %w", err)
	}
	bp.Resources = append(bp.Resources, resources...)
}
```

## Steps to Reproduce
1. Generate a project with `cf gen --template-source=FileSystem`.
2. Inspect the generated Composition:
   ```yaml
   input:
     apiVersion: gotemplating.fn.crossplane.io/v1beta1
     kind: GoTemplate
     source: FileSystem
     fileSystem:
       dir: templates/my-comp
   ```
3. Run `cf adopt --xrd <xrd.yaml> --composition <comp.yaml>`.
4. Command exits 0 with no errors.
5. Inspect the output blueprint: `resources` is `[]` (empty), and `lossReport` reports 0 dropped fields, 0 unmapped items.

## Expected Behavior
When `source: FileSystem` is encountered:
1. If templates can be loaded from the referenced filesystem directory, `Adopt` should parse the templates into blueprint resources.
2. If `source: FileSystem` cannot be resolved (or single-file adopt is performed), it MUST record an explicit loss in `LossReport` stating that resources defined in `fileSystem.dir` could not be adopted, rather than silently dropping them.

## Severity
`severity:P1` — Silent data loss during adoption without notification in `LossReport`.
