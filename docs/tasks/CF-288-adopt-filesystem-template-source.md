## Symptom

When adopting a Composition that uses `function-go-templating` with `source: FileSystem` (as generated by `cf gen --template-source=FileSystem` or created by teams storing templates in external directories), `Adopt` in `internal/adopt/adopt.go` silently ignores all resources defined in external files without parsing them and without recording any notification or warning in `bp.LossReport`. The tool exits 0 while producing an empty blueprint (`resources: []`) and an empty `LossReport`.

## Evidence

Given a Composition using `source: FileSystem`:

```sh
$ cat << 'EOF' > /tmp/test_comp_fs.yaml
apiVersion: apiextensions.crossplane.io/v1
kind: Composition
metadata:
  name: test-fs-comp
spec:
  compositeTypeRef:
    apiVersion: example.org/v1alpha1
    kind: XTest
  mode: Pipeline
  pipeline:
  - step: go-templating
    functionRef:
      name: function-go-templating
    input:
      apiVersion: gotemplating.fn.crossplane.io/v1beta1
      kind: GoTemplate
      source: FileSystem
      fileSystem:
        dir: templates/my-comp
EOF
$ ./bin/cf adopt /tmp/test_comp_fs.yaml
```

Output:
```
apiVersion: factory.crossplane.io/v1alpha1
kind: Blueprint
metadata:
  name: test-fs-comp
spec:
  resources: []
```

Exit code is 0, stderr is empty, and `LossReport` records 0 dropped fields and 0 unmapped items.

Reproduced on commit `1c1374e`.

## Acceptance test

```go
// internal/adopt/adopt_test.go
func TestCF288_FileSystemTemplateSourceLossReported(t *testing.T) {
	manifest := []byte(`apiVersion: apiextensions.crossplane.io/v1
kind: Composition
metadata:
  name: test-fs-comp
spec:
  compositeTypeRef:
    apiVersion: example.org/v1alpha1
    kind: XTest
  mode: Pipeline
  pipeline:
  - step: go-templating
    functionRef:
      name: function-go-templating
    input:
      apiVersion: gotemplating.fn.crossplane.io/v1beta1
      kind: GoTemplate
      source: FileSystem
      fileSystem:
        dir: templates/my-comp
`)
	bp, report, err := Adopt(manifest, Options{})
	if err != nil {
		t.Fatalf("Adopt failed: %v", err)
	}
	if len(bp.Spec.Resources) != 0 {
		t.Fatalf("expected 0 resources, got %d", len(bp.Spec.Resources))
	}
	if len(report.DroppedFields) == 0 && len(report.Unmapped) == 0 {
		t.Fatal("expected loss report entry for source: FileSystem, got none")
	}
	found := false
	for _, dropped := range report.DroppedFields {
		if strings.Contains(dropped.Field, "fileSystem") || strings.Contains(dropped.Reason, "FileSystem") || strings.Contains(dropped.Reason, "fileSystem") {
			found = true
			break
		}
	}
	if !found {
		for _, unmapped := range report.Unmapped {
			if strings.Contains(unmapped, "fileSystem") || strings.Contains(unmapped, "FileSystem") {
				found = true
				break
			}
		}
	}
	if !found {
		t.Fatalf("expected loss report to mention FileSystem, got dropped: %+v, unmapped: %+v", report.DroppedFields, report.Unmapped)
	}
}
```

## Contract

1. In `internal/adopt/adopt.go`:
   - When inspecting `function-go-templating` steps, detect if `source: FileSystem` or `fileSystem` configuration is specified without an inline template.
   - If `source: FileSystem` is encountered during manifest adoption:
     - Record a loss entry in `report.Record(...)` or `report.DroppedFields` indicating that external template directories (e.g. `spec.pipeline[step].input.fileSystem.dir`) cannot be resolved from manifest input alone.
2. The exit code must reflect the loss report in accordance with CLI flags (e.g., exit 2 when loss occurs).
